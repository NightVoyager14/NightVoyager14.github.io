# 视觉验收协议

**可复现的视觉验证流程。** 本文把「改视觉要仔细看」变成有具体命令、
具体产物、具体判定标准、具体失败回退的协议。

> 为什么需要本文：视觉改动曾是本项目最薄弱的一环 ——
> v2.2.0 迁移了配色 token 与网格却**没迁移设计本身**，
> 而当时的验收只断言了「属性正确、没有溢出」，于是被用户一眼看出。
> **属性通过 ≠ 设计迁移到位。**

---

## 适用时机

改下列任一内容后**必须**执行本协议：

- `style.css`（任何视觉相关改动）
- `index.html` 的结构 / class
- 主题 token、字号系数、圆角、描边、材质
- 新增或修改图例、状态徽章、标签

`docs/` 或 `CHANGELOG.md` 的纯文字改动**不需要**。

---

## 前置条件

1. 本地服务器已启动（在仓库根目录）：

   ```bash
   python -m http.server 8080
   ```

2. 报告目录存在且**已清空上一轮产物**：

   ```bash
   rm -f .analysis/*.json .analysis/_shots/*.png
   ```

3. 运行环境能启动 Chromium。
   受限沙箱下会以 `FATAL:mojo ... Check failed: 拒绝访问 (0x5)` 失败，
   随后 Playwright 报 `PermissionError: [WinError 5]` —— 此时需提升权限。

## 步骤 1 · 与设计基准逐项比对

```bash
python .analysis/parity_probe.py
```

**产物**：`.analysis/parity.json`

**判定**：该探针把生产页与 `preview.html` 的以下量并排导出，逐项应一致或符合预期差异：

| 比对项 | 说明 |
| --- | --- |
| 列宽比 | 左宽右窄（`1.15fr : 1fr`） |
| `gap` | `22px` |
| 对齐方式 | `align-items: start` |
| 色值 | 各主题 token 实际生效值 |
| 圆角 | 三档：2 / 5 / 12px |
| 描边宽度 | `1.5px` |
| 字号系数 | `--n` = 22 / 24 / 26 |

**失败回退**：某项不一致 → 用 computed style 查真实生效值，
按 [development.md](development.md#css-权重约定) 排查权重，**不要靠肉眼判断**。

---

## 步骤 2 · 吸附与阶段行为

```bash
python .analysis/scroll_probe.py
python .analysis/verify_probe.py
```

**产物**：`.analysis/scroll.json`、`.analysis/verify.json`

**判定**：

| 项 | 标准 |
| --- | --- |
| 吸附行程 | 滚到页面各位置时 `hero.top` 保持 `16`（顶部未吸附时除外） |
| 主倒计时可见性 | 除页面最顶部外，任何滚动位置都**不得**完全移出视口 |
| 「回到当前阶段」 | 查看历史/未来阶段时可见；查看当前阶段时隐藏 |

**失败回退**：`hero.top` 变化 → 检查左栏 `grid-row` 是否跨到页脚行。

---

## 步骤 3 · 主题 × 视口矩阵

```bash
python .analysis/prod_probe.py
```

**产物**：`.analysis/prod.json`

**判定**：5 主题 × 4 视口（390 / 834 / 1023 / 1280）= **20 组**，
`overflowX` 必须**全为 0**。

---

## 步骤 4 · 对比度（必须做 alpha 合成）

```bash
python .analysis/final_probe.py
```

**产物**：`.analysis/final.json` + `.analysis/_shots/` 下的主题截图

**判定**：各主题实色块上的文字对比度 **≥ 4.5:1**。

> ⚠️ **必须把 `rgba` 底色与父元素合成后再算对比度。**
> 不做合成会算出假的高分 —— 夜航主题的 Hero pill 曾因此被误判为
> 「2.11:1，已修好」，而真实值是 **1.18:1**，于是错误地「修」了一轮。

---

## 步骤 5 · 人眼复核截图

**这一步不能跳过，也不能用断言替代。**

```bash
python .analysis/b345_probe.py     # 产出 Hero / 假期卡 / 日历卡截图
```

打开 `.analysis/_shots/` 下的 PNG，逐个确认：

| 检查 | 看什么 |
| --- | --- |
| 层级 | 卡内是否存在两个并列的同等元素（这是「标签与徽章并排不协调」的成因） |
| 对齐 | 装饰性元素（菱形、连接线、方点）是否与文字的视觉中心对齐 |
| 一致性 | 图例样例与实际单元格是否是同一种样式 |
| 完整性 | 新设计语言是否真的落到了每个组件上（不是只改了 token） |
| 材质 | 斜纹 / 网格纹理是否正确显示 |
| 留白 | 卡片内边距、间距是否与 demo 一致 |

**判定**：截图与 `preview.html` 同区域的观感一致。
发现不一致 → 回到步骤 1 定位是哪条规则。

---

## 步骤 6 · 关键区域截图归档

对以下区域各截一张（用于对比改动前后）：

- 阶段轨道（含四态节点与连接线）
- 日历卡（含图例、农历、节气）
- 日程卡（含标签与徽章）
- 全屏层
- 浮动小窗
- 设置弹窗
- 日期选择器

## 验收清单

- [ ] `parity.json` 各项与 demo 一致或差异符合预期
- [ ] `scroll.json` 吸附行程恒定，主倒计时不消失
- [ ] `verify.json` 阶段切换与返回按钮行为正确
- [ ] `prod.json` 20 组溢出全为 0
- [ ] `final.json` 对比度全 ≥ 4.5:1（**已做 alpha 合成**）
- [ ] `.analysis/_shots/` 截图**已人眼复核**，与 demo 观感一致
- [ ] 关键区域截图已归档

## 常见失败模式

| 症状 | 最可能的原因 |
| --- | --- |
| 属性全绿但用户说「没迁移设计」 | 只跑了步骤 3，跳过了步骤 1 和 5 |
| 样式改动「看着生效实际没有」 | CSS 权重被后置规则压回，见 [development.md](development.md#css-权重约定) |
| 图例承诺的样式格子里没有 | 图例与单元格由两套不同规则控制 |
| 对比度「通过」但实际不可读 | 没做 alpha 合成 |
| 装饰元素看起来「歪」 | 用了宽度算垂直中心，但元素是 border-box（应按真实渲染高度算） |
| 读了旧结果宣布通过 | 报告文件未清空，读到上一轮产物 —— **先清空再运行，运行后确认 mtime 是新的** |
