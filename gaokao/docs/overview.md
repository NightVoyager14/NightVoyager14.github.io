# 项目概览

## 这是什么

一个**纯静态、零依赖、零构建**的四川 3+1+2 新高考倒计时与日程页面。

- 线上地址：<https://www.nightvoyager.online/gaokao/>
- 归属：NightVoyager 的个人 GitHub Pages 站点，应用本身全部位于 `gaokao/` 目录
- 当前版本：**v2.5.2**（版本号唯一来源是 `time.js` 的 `APP_VERSION`）

「零依赖」是字面意思：没有 `package.json`、没有 `node_modules`、没有构建步骤。
浏览器直接打开 `index.html` 就能跑（但 Service Worker 与 PWA 安装需要 http/https，
见 [deployment.md](deployment.md)）。

## 解决什么问题

面向**四川新高考考生**，把三件事集中在一屏里：

1. **离高考还有多久** —— 总倒计时 + 9 场科目逐场倒计时
2. **现在处于哪个阶段** —— 零诊 / 一诊 / 二诊 / 三诊 / 高考 五阶段预报
3. **接下来怎么放假** —— 节假日日历（含农历与二十四节气）

它同时是一个**长期维护的个人项目**：作者自述「没怎么写过前端，就直接用 AI 了」，
因此文档、验证脚本、单一数据源约定在这里不是可选项，而是让项目能被继续改下去的前提。

## 设计目标与取舍

### 目标

| 目标 | 具体体现 |
| --- | --- |
| **零依赖零构建** | 只输出 HTML/CSS/JS，`git push` 即发布；没有工具链会过期 |
| **时间绝对正确** | 全部以北京时间（UTC+8）为基准，非 UTC+8 用户不会偏移 8 小时 |
| **单一数据源** | 年份、版本号、考试时间、节假日、节气各自只有一处权威来源 |
| **离线可用** | Service Worker 缓存全量资源；数据有内置兜底表，网络失败也能渲染 |
| **可访问** | 键盘可达、`aria` 语义、`prefers-reduced-motion`、读屏播报 |
| **视觉有性格** | 五套主题，其中「露营」对照《摇曳露营△》的配色与形状语言 |

### 明确的取舍

| 取舍 | 决定 | 理由 |
| --- | --- | --- |
| 节假日数据来源 | **不请求第三方 API**，用本地 JSON + 内置兜底 | 法定节假日一年一变；引入运行时网络依赖会带来可用性耦合、CORS、离线失效与隐私成本 |
| 农历计算 | **自己算**（朔表 + 冬至规则），不引库 | 需要跨越 2026–2028 且要能校验；一个精简朔表 95 个数字即可覆盖 8 年 |
| 节气数据 | **官方值 + 近似值两级** | 官方未公布的年份只给日期、不给时刻 —— 宁可少给信息，也不给未经核对的分钟数 |
| 字号缩放 | 用 `container query` 的 `cqw`，不用 `vw` | `vw` 在窄卡片里必然溢出；`cqw` 以卡片自身宽度为基准 |
| 滚动锁 | **冻结滚动位置**，不改 `overflow` | `overflow: hidden` 会改变 sticky 的滚动容器，导致吸附的主倒计时消失 |
| 双栏归属 | 页头与阶段轨道**全宽**，两栏只承载内容 | 对齐设计基准 `preview.html`；也是 v2.3.0 修掉「页头标题跑到最下方」的结构基础 |

## 浏览器支持

| 功能 | 支持情况 |
| --- | --- |
| 倒计时、阶段、选科、主题、日历、农历节气 | 所有现代浏览器 |
| Hero 大数字的 `cqw` 容器查询字号 | 支持容器查询的浏览器；不支持时回退 `--n-fallback`（保守的 `vw` 系数） |
| 全屏模式 | 优先 Fullscreen API；不可用时退化为同一套全屏覆盖层（故 iOS 也能用） |
| 浮动小窗 | 仅 Chromium 116+ 的 Document Picture-in-Picture |
| Service Worker / 离线 / 安装 | 需 http/https（`file://` 下代码有协议守卫，跳过注册） |
| 键盘操作、`prefers-reduced-motion` | 已适配 |

## 边界与已知限制

以下是**真实存在**的限制，不是待办清单的美化说法：

1. **依赖设备本地时钟**。页面不做服务端校时（这是刻意的产品决策，见
   [architecture.md](architecture.md)）。设备时间错误时倒计时也会错。
2. **2027 年节假日为预估**。官方通常在当年 11 月前后发布次年安排；
   发布前界面以「预估」标签区分。
3. **2028 年 2 月以后的节气只有日期、没有时刻**，且由近似式推算。
   官方表发布后补进 `data/solar-terms.json` 即可。
4. **农历朔表覆盖约 2024-05 ~ 2029-12**。超出范围的日期 `getLunar()` 返回 `null`，
   界面不显示农历（不会报错）。
5. **考前不足 24 小时显示「0 天」**。这是整日截断的结果，属于已知的文案取舍，
   未做特殊处理。
6. **左栏留白较多**。左栏只有 Hero 与假期卡，长页面上下方留白明显。
   这是设计基准 `preview.html` 本身的比例，要填满需要改信息架构。
7. **`.analysis/` 下的验证脚本不入库**。它们是本地工具，依赖 Python + Playwright
   与沙箱外的权限。详见 [testing.md](testing.md)。
