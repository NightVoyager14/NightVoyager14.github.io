## 一、demo 的设计总结

### 1.1 布局骨架（自上而下，5 层）

| 层 | demo 选择器 | 说明 |

| 阶段轨道 | `.rail` | **全宽**，一条连续路径：页眉「考试阶段 / 当前：高考」+ 5 个菱形节点，节点间横线相连 |

| 页脚 | `.pg-footer` | 全宽，「金榜题名 · 前程似锦」 |

### 1.2 配色

- 5 套主题：`night` 夜航 / `ink` 砚台 / `board` 白板 / `celadon` 青瓷 / `camp` 露营。全部挂在 `[data-theme]` 上做 **token 覆盖**，组件 CSS 零改动。
- token 契约（**共 26 个**）：`--bg --bg-soft --bg-card --bg-card-hover --bg-inset --text --text-2 --text-3 --accent --accent-weak --accent-text --info --info-weak --ok --ok-weak --border --border-strong --shadow --shadow-lift --font-display --font-heading --card-tint --card-accent --card-solid-bg --card-solid-fg --card-solid-line --info-block --info-block-fg`
- **露营主题是唯一「大胆用色」的**：4 个实色块 `--camp-sun #E8892B` / `--camp-sky #8FD3E8` / `--camp-tree #A7D9A0` / `--camp-sand #F7CE6B`，前景统一 `#1F1A12`（对比度 6.5–10.9:1）。
- 其他 4 套主题：`--card-solid-bg` 退回 `var(--bg-card)`，**彩块自动降级成普通卡片**，所以彩块类可以安全复用。

### 1.3 形状与材质语言（反「AI 味」的核心）

- **圆角刻意见三档**：`--r-sharp 2px`（标签/图章/进度段）、`--r-btn 5px`（按钮/chip/考试卡）、`--r-card 12px`（卡片，唯一大圆角）。**不做「一圆到底」**。
- **实色描边替代柔和投影**：`--bd: 1.5px` + 硬阴影（露营 `0 2px 0`／夜航柔和深影）。
- **形状分化**：`.card--notch` 右下缺角 + 可见折边（`clip-path`）；`.cal-day.holiday` 单独放大到 `8px` 圆角，与周围 `3px` 方格形成反差。
- **材质分化**：地图网格纹理（`repeating-linear-gradient` 双层，纯 CSS 零资源）铺在阶段轨道上；日程卡铺 45° 斜纹，与其他卡片的纯白拉开材质差。
- **卡内页眉 `.card-band`**：一块窄实色横条，给整卡一个「色块起点」。

### 1.4 组件规格

| 组件 | 关键规格 |
| --- | --- |
| Hero 大数字 | `container-type: inline-size` + `font-size: calc(var(--n) * 1cqw)`；`--n` 22/24/26 对应三档字号；`white-space: nowrap` 绝不允许折行；单位随数字 baseline 对齐 |
| Hero 精确行 `.h-sub` | 左侧 `3px` 实色竖线，等宽字体，与数字同色 |
| 状态 pill | `--r-sharp` 直角、`4px 9px`、`6px` 方点（`.dt.pulse` 呼吸）；Hero 内改 `rgba(255,255,255,.55)` 底 |
| 阶段节点 `.step .dot` | **旋转 45° 的方块（菱形）**，不是圆点；已结束=实心灰、进行中=强调色+光晕、当前=强调色描边、未来=虚线 |
| 考试卡 `.exam` | `grid 1fr auto`；**左侧 3px 实色竖条**做状态标记（不用整块淡底）；`.selected` 竖条+科名变强调色、`.dimmed` 透明度 .4 + 删除线 |
| 日期分隔 `.day-head` | 等宽字体日期块（`--r-sharp` 实色底）+ 星期文字 |
| 场次分隔 `.sess` | 左右两条 1px 细线夹住「上午场 / 下午场」 |
| 选科 `.chip` | `--r-btn` 近直角方块，**不是胶囊**；选中=强调色实底 |
| 日历 `.cal-day` | `min-height: 56px`；放假日整格强调色 + `8px` 圆角；调休日 45° 斜纹；预估日天蓝整格；今天=2px 描边 + 底部方点 |

### 1.5 已踩的坑（demo 注释里逐条留了说明，迁移必须继承）

1. **`overflow: hidden` 会裁掉旋转 45° 的菱形节点顶部** → `.rail-steps` 明确不加 `overflow`。
2. **`clip-path` 在圆角与阴影之后应用，外投影会被裁** → `.card--notch` 只用在**不依赖外投影**的卡片上。
3. **`.hero .h-num` 的 `flex-wrap: nowrap` 拦不住文字换行** → 必须额外写 `white-space: nowrap`，否则整行塌缩。
4. **字号不能用 `vw`** → 窄卡片里必溢出；要么 `cqw`，要么 JS 实测。
5. **`--card-solid-*` 必须有中性兜底**，否则非露营主题上彩块类会变成空白。
6. **实色卡上的标题要走卡片前景色** → 否则浅字压浅底糊成一片。
7. **Hero 里的 pill 不能再用浅底浅字** → 实色 Hero 上必须换 `rgba(255,255,255,.55)`。
8. **不要给所有东西统一大圆角**。

### 1.6 生产端本轮新增的坑（本轮实测发现）

9. **CSS Grid 会把「未显式指定区域」的子元素按文档序自动放置**。生产页 `.main-content` 使用了 `grid-template-areas: "left right" / "footer footer"`，而 `.header` 没有分到区域，于是被自动放到了最后一行隐式行 —— **页头标题跑到了整页最下方**（实测 `header.y = 1547`，而页脚 `y = 1487`）。修复：给 `.header` 显式 `grid-area: head`，并把 `head` 与 `rail` 两行加入 `grid-template-areas`。

### 4.3 已知遗留

1. **本地预览的 MIME 报错**：`python -m http.server` 把 `.js` 发成 `text/plain`，
   导致 Service Worker 注册被拒并留下一条控制台错误。GitHub Pages 正常，与代码无关。
   已在 README 记录。
2. **左栏较空**：左栏只有 Hero + 假期卡，右栏有四张卡，长页面上左栏下方留白较多。
   这是 demo 本身的比例，如需填满需要改信息架构（把某张卡移到左栏），属设计决策。
3. **两栏比例按 demo 取左宽右窄**：日历卡与日程卡因此比左栏窄。
   若认为「日程是主角」应更宽，需要把比例反过来，同样属设计决策。

## 七、后续改动必须遵守的三条

1. **`.main-content` 的直接子元素必须显式给 `grid-area`**，否则会被 Grid 自动放置到
   最后的隐式行（页头标题掉到页脚下面就是这么来的）。
2. **`#pgColLeft` / `#pgColRight` 是吸附与双栏的唯一载体**。要调整栏内顺序，
   请改 HTML 顺序，不要改这两个包装 div 的结构。
   **左栏的 `grid-row` 必须跨到页脚行**（`"left right" / "left footer"`），
   否则 sticky 行程会在页脚之前用尽，滚到最下方时主倒计时会掉出视口。
3. **改视觉必须与 `preview.html` 对照**，并跑一遍
   `parity_probe.py`（本文档 A28 的数据来源）。
   只断言「没有溢出」是不够的 —— 属性通过不代表设计迁移到位。

## 十一、v2.4.0 · 农历与二十四节气

### 11.1 架构

新增 `lunar.js`：纯函数模块，**不碰 DOM**，不改动 `time.js` 的既有结构。
加载顺序变为 `time.js → lunar.js → gaokao.js`。

### 11.2 农历算法（真算，不是查表）

1. Meeus 朔望月近似式（含主要摄动项）→ 每个「朔」的北京日期，见 `NEW_MOON_DAYS`；
2. 编号规则：**包含冬至的那个朔望月为十一月**，其后递增、逢 12 归 1；
3. 日序 = 北京日期距该月月首的天数。

**校验**：用用户提供的 2026 年节气表里的 24 个农历日期逐条比对，
浏览器内 **24/24 一致**（含 `2026-12-22 → 十一月十四`、`2027-01-20 → 腊月十三`
两个跨年边界）。

### 11.3 节气数据的分级

| 年份 | 来源 | 界面显示 |
| --- | --- | --- |
| 2026 | 官方表，精确到分 | 名称（精确时刻在 `aria-label` 里） |
| 2027 年 1-2 月 | 官方表跨年部分 | 名称 |
| 其余 | 近似式 + 逐月校正（7/8/9/10 月 +2 天） | 名称，不给时刻 |

原则：**宁可少给信息，也不给未经核对的分钟数**。

### 11.4 三条新增硬约束

1. **两套「日序号」口径不可混用**：`cnDayNumber()` 是 1970 基，
   `lunarEpochDay()` 是 2000 基（差 `LUNAR_EPOCH_DAY`）。混用会**静默**显示不出农历。
2. **校验数据必须与生产代码同一口径**。本轮中途用过一个自洽但整体偏移 11 天的朔表，
   它「通过」了全部 24 条参照 —— 因为编号规则会自我补偿偏移。
   真正暴露问题的是把朔表数值与浏览器里 `bjDate` 的实际天数对照。
   **自洽不等于正确。**
3. **图例样例必须与实际单元格同源**。v2.4.1 一次修了三处「图例有的格子没有」：
   今天描边被更高权重压回 1px、节气只有文字没有方框、格子圆角 3px 而图例 2px。
   三者都是「两套规则各画各的」。新增图例项时，样例与单元格应复用同一个
   `--r-*` 变量与同一个 border 声明。
